# 4. Pictures and galleries

Portfolio & Agency Site Template by The Diamond Empire, https://thedempire.shop/

The sample case studies use generated placeholder artwork: plain SVG files in `public/work/<case-study>/`. They are not photographs and they are meant to be replaced. This guide explains the rules, which keep pages from jumping while pictures load.

## Where pictures go

Put the files for a case study in `public/work/<case-study-name>/`, next to the other case studies, and list each one under `images` in the front matter of `content/work/<case-study-name>.mdx`:

```text
images:
  - id: cover
    file: cover.jpg
    alt: "A short description of the picture"
    caption: "Optional caption shown under the picture"
    width: 1600
    height: 1000
```

- `id` is the name you use in `<Figure id="..." />` and `<Gallery ids="..." />`.
- `file` is the file name in the case study's folder. If you leave it out, the file is `<id>.svg`.
- `width` and `height` are the picture's real size in pixels. They are required. The site gives every picture a frame with that shape, so the page does not move when the picture arrives, and the build stops if they are missing or are not whole numbers.
- `alt` is required. Describe what the picture shows and why it is there, in a sentence a person could read aloud. Use different text for each picture.

## Sizes and formats

- Export photographs as JPG, WebP or AVIF, and illustrations as SVG or PNG. Keep each file as small as you can: a cover rarely needs to be more than about 1600 pixels wide, or 200 kB.
- The site does not resize pictures for you (that needs a server). If you want browsers to choose a smaller file on small screens, export smaller copies and list them as variants:

```text
    variants:
      - file: cover-800.jpg
        width: 800
      - file: cover-400.jpg
        width: 400
```

The site writes a `srcset` from the main file and its variants.

- The first picture on every page loads straight away; every other picture loads when the visitor scrolls near it.

## What `npm test` checks

- Every picture named in a case study exists in `public/`.
- An SVG picture states the same width and height as the front matter.
- No picture in `public/work/` is left unused.
- Every picture in a case study has its own alt text.

Raster pictures (JPG, PNG, WebP) cannot be checked for their real size by these tests, so check by hand that `width` and `height` match the file.

## Photographs of people

The Team page shows a drawn stand-in for each person so that no portrait is needed. If you add photographs, get each person's permission, give each picture alt text that names the person, and keep the file small.

## The sample artwork

The placeholder files were generated by a script that is part of the template's development repository and is not included in this package. Delete the sample case studies and their folders in `public/work/` when you replace them.
